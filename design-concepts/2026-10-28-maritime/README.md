## 推荐组合

建议先选 A：前台以克制的港口影像建立物流行业辨识度，后台使用浅底、细线、明确表头和真实业务密度。若更偏向欧洲货代品牌气质，可采用 B 首页，同时沿用 A 工作台的结构。

减少原站的渐变光晕、玻璃面板、装饰性技术网格、过量大圆角和首次进入片头。用业务信息层级、照片构图、字体与留白体现设计，而非堆叠装饰。

## 可演示的操作

- 顶部页面选择器切换 9 个设计页；首页查询跳转至追踪结果。
- 追踪参考号可编辑，结果明确标注为样例，不查询真实承运人。
- 箱型类别可切换；装箱页可切换箱型并预览反馈，数值与示意图不参与算法运算。
- 工作台可筛选状态、搜索票单、查看详情抽屉和新建侧栏。
- 登录按钮进入等待页，不需要真实凭据；等待页可手动切换加载、超时、无权限及空数据状态，并演示重试。
- 除已完整设计的页面外，侧栏部分业务模块仅展示导航说明抽屉，不代表这些页面已经实现。

## 视觉约定

- 主色：`#15384A`；行动色：`#BA4B25`；背景：`#F2F5F6`。
- 状态同时使用文本与颜色；主要操作与次级操作区分明确。
- 桌面内容最大宽度 1220 px；移动端边距 18 px；以 8 px 作为间距节奏。
- 圆角以 2–4 px 为主。工作台以信息为主，不沿用官网的大标题与摄影区。
- 无衬线字体；首页标题桌面 62 px、移动 44 px；内页 38 px；工作台 28 px。
- 常规交互过渡 180 ms；支持减少动态效果；快速跳转无需展示整页等待。
- `LP` 为临时文字标记，不是正式商标设计。后续可替换为公司授权 Logo。

## 技术评估摘要

现有 Vue 3/Vite/Element Plus + Spring Boot/Java + MySQL + Node/Playwright 追踪服务分工合理，模块注册、接口契约、适配器协议、Flyway 和 CI 已提供扩展基础。**没有必要为了优化 UI 再换一套技术栈。**

仍是渐进重构：部分页面和 Service 体积较大，公开追踪页仍有独立的原生 DOM 前端；类型及规范检查是部分覆盖。本次 `module-platform` 检查 24/24、OpenAPI 一致性检查通过；前端 typecheck 发现 `ShipmentListWorkspacePage.vue:492` 的 `batchTrackReferenceType` 返回类型不一致。未运行完整后端、数据库、Docker 或真实船司验收。

## 落地顺序

1. 先修现有 typecheck 错误，确保迭代有可用基线。
2. 从本提案确定首页方向与品牌资产，建立可供 Vue 和追踪页共用的 CSS tokens。
3. 提取 PublicLayout、WorkspaceLayout、AuthLayout，以及按钮、表单、状态、表格、抽屉基础组件。
4. 改造官网和公开追踪页。公开追踪在 `tracking-service/public`，不可只改 Vue 全局 CSS 后就认为全站完成。
5. 按模块改造工作台与管理页，保持现有角色鉴权、接口及适配器协议。
6. 接入真实加载、超时、异常与无权限反馈，取消装饰性强制等待。
7. 最后验证真实业务流程、权限矩阵、手机断点和键盘可访问性。
