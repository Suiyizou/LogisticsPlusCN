## 已落地的交付点

1. **统一数据访问**：Spring Boot 3 / MyBatis-Plus 3.5.12，普通 CRUD 经受控 Repository；公告与客户基本资料完成真实业务迁移。复杂查询、复合键与特定并发操作保留显式 Mapper。
2. **可运行模块生成器**：规格生成内部参考模块的后端分层、DTO、字段映射、V4 迁移、前端页面骨架、语言包与注册记录；服务目录为完整样板。保护手工代码、已有业务模块、历史表和已发布迁移。
3. **统一接口契约**：OpenAPI 类型与 openapi-fetch 客户端；客户目录实际消费类型客户端。明确 PATCH 缺省/null、版本冲突、分页与错误行为，隔离客户/员工凭据并防止旧请求污染新会话。
4. **统一前端宿主**：business/admin/customer surface、导航、懒加载和模块语言包。管理员已有页面纳入注册式加载，客户独立宿主使用客户范围 API。
5. **统一数据库演进**：Flyway 代替多个业务启动建表器；显式旧库审核/备份校验/baseline 0 接管，普通启动禁止自动接管非空库。迁移矩阵进入 Docker CI。
6. **统一 Node 扩展点**：船司适配器注册，统一准备、执行、健康状态和资源释放；HTTP 分发不再堆叠船司条件分支。

## 后续模块的标准开发路径

1. 先确定领域归属、员工/客户数据范围与公开 DTO。
2. 普通内部参考模块复制 `module-specs/service-catalog.json`，执行 `npm run module:create -- <spec> --dry-run` 审核后生成。
3. 在 application/domain/workflow 实现真实业务规则，通过公开端口协作；不要直接引用其他模块私有状态。
4. 增加可空字段可生成增量迁移；必填、重命名、类型变化、删除与回填采用分阶段迁移并人工审核。
5. 执行 `npm run verify`；数据库变化另跑 `node scripts/verify-database-ci.mjs`。有历史库时先导入隔离副本演练显式接管。

移动已有模块主要调整注册的 surface/navigation/mount；URL 改变需要兼容跳转。移到客户端必须配套客户范围 API，菜单位置不会替代授权。

## 明确边界

- 普通 CRUD 和兼容字段扩展可生成 SQL，复杂业务状态、跨企业授权、金额及历史数据修复仍需要明确设计和代码；不承诺任意业务零代码。
- 生成器当前限定内部参考数据，不直接生成客户订单/保险/财务等复杂业务系统。
- 没有宣称已清除全部历史 SQL；保留复杂读查询、复合键与原子操作是有意选择。
- 远端 Gitee CI 未在本轮触发；本地同入口验证不能冒充远端流水线通过。
- 未执行生产数据库迁移、服务器发布、Git 提交或推送；历史 SQL 仅在隔离副本上验证。
