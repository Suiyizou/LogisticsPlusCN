# 货踪系统使用教程（大白话版）

> 这套系统解决一件事：**船司官网的货踪只能人肉查，我们让它自动查，并把结果变成能入库、能渲染的 JSON。**

---

## 一、先说清楚它长什么样

```
业务员/客户在页面提单号
        ↓
云端 Java 后端（你项目里那个）
        ↓  frp 内网穿透（服务器 18791 → 我家电脑 8791）
我本机的队列服务 + 真 Chrome
        ↓
船司官网（COSCO / SML / MSC …）
        ↓  抓回来的页面 → 统一 JSON（tracking.v1）
云端 Java 后端：转换 → 入库 → 返回快照
        ↓
页面渲染（船期节点、箱号、时间线）
```

**关键点**：船司官网会检测机器人，所以查询必须在**一台有真桌面、真 Chrome**的电脑上跑。
服务器上没有浏览器，它只负责调度和渲染。这就是为什么要内网穿透。

---

## 二、我本机要保证什么（3 个进程）

| 进程 | 干嘛的 | 怎么起 |
|---|---|---|
| **专用 Chrome** | 真正去船司官网查 | `node scripts\start-chrome.mjs` |
| **队列服务** | 排队、驱动 Chrome、抽字段、出 JSON | `node scripts\serve-track.mjs`（`CONCURRENCY=1`） |
| **frpc** | 把本机 8791 穿到服务器 18791 | 已做成系统服务，**自动跑，不用管** |

一键启动：`D:\AI\shipping-tracking\deploy\frp\start-all.bat`

**日常只要记住三件事**
1. Chrome 那个窗口**别关**
2. 服务**只留一份**（重复启会端口冲突）
3. 电脑**别休眠**（休眠=隧道断=查不了）

---

## 三、船司需要登录的怎么办

有些船司（COSCO、MSC、CMA 等）要登录才能查到全部信息。

- 在本机那个**专用 Chrome 窗口**里手动登录一次
- 登录态保存在专用 profile（`D:\AI\chrome-automation-profile`），**长期有效**
- 之后所有查询都复用这个登录态，不用反复登

---

## 四、页面/后端怎么用（关键几条）

**页面 → Java 后端**
```
POST /api/public/shipments/track
{ "carrier":"COSCO", "type":"BILLOFLADING", "number":"COSU9510184670", "forceRefresh":true }
```
- `carrier` 用平台编码；**传给本地服务前要转成本地编码**：`CMA → CMA_CGM`、`HPL → HAPAG_LLOYD`，其余同名
- 实时查询要业务员/管理员权限；客户 token 只能读已入库快照

**Java 后端 → 本机队列服务**（带 `Authorization: Bearer <业务令牌>`）
```
POST /jobs                      提交，返回 job_id（HTTP 202）
GET  /jobs/{id}                 每 2 秒轮询进度
GET  /jobs/{id}/result          结果（409=还没好，继续等；200=拿到）
POST /jobs/{id}/cancel          超时/用户取消
GET  /health                    服务是否在线
```

**判断成败不能只看 job.status**，要看每条的 `items[].status`：

| item 状态 | 含义 | 后端应返回 |
|---|---|---|
| `done` | 查到了 | 200 |
| `human_required` | 船司要人工验证（如万海 hCaptcha） | `409 TRACKING_HUMAN_REQUIRED` |
| `no_business_data` | 页面能开但查不到这票 | `404 TRACKING_NO_BUSINESS_DATA` |
| `carrier_not_implemented` | 船司编码没对上 | 修映射 |
| `failed` | 报错（含重试后） | 502/503 |

## 五、拿到的是什么数据

一份统一 JSON（`tracking.v1`），每条提单里包含：

- **船司**：编码、名称、SCAC
- **查询**：原单号、实际提交的单号、单号类型、耗时
- **箱**：箱号、箱型、运输方式、条款、当前位置、最新状态、状态时间
- **航线**：起运地 → 目的地、船名航次、ETD/ETA/ATD/ATA
- **4 个节点**：起运 / 离港 / 到港 / 最终目的地（有就给，没有为 null）
- **事件时间线**：按时间排列的全部动态
- **分段运输**：多段航线时，每段的船名、装卸港、时间
- **告警**：哪些字段没抽到（比如"SML 页面没有船名这一列"）

⚠️ 三条铁律：
1. 抽不到的字段**就是 null**，不会瞎猜
2. `businessVerified` 固定 `false` —— 查到不等于业务已人工核验
3. 截图/文本路径是本机的，**不给页面用**

## 六、常见问题（照着查就行）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 全部查询失败 | 本机 Chrome 没开 | 起 Chrome，别关窗口 |
| `503 TRACKING_LOCAL_UNAVAILABLE` | 隧道断 / 本机休眠 | 看本机 `frpc` 是否在跑，电脑是否休眠 |
| 一直 `human_required` | 船司要求验证码 | 在专用 Chrome 里人工过一关，之后复用 |
| `404 no_business_data` | 这票官网确实没数据 | 换单号类型（订舱号/提单号）再试 |
| 某家港口/船名总是空 | 该船司页面本身没这列 | 正常，属页面限制（SML/MATSON 就是） |
| 查询很慢（40–60s） | SML/MSC 页面本身慢 | 正常，后端总超时留 7 分钟 |
| 401 | 业务令牌两边不一致 | 本机 `TRACK_TOKEN` 与后端 `APP_TRACKING_LOCAL_TOKEN` 必须完全相同 |

## 七、安全须知（别省）

1. **18791 现在对全网开放且无业务令牌** → 建议在云安全组限制成「只有 Java 后端那台机器能访问」
2. frp 隧道令牌（`auth.token`）和业务令牌（`TRACK_TOKEN`）是**两回事**，都要保管好
3. 本机服务只监听 `127.0.0.1`，不要改成对局域网开放

## 八、术语小抄

| 词 | 意思 |
|---|---|
| **SCAC** | 船公司四位代码，如 `COSU`(中远)、`MEDU`(地中海)、`MAEU`(马士基) |
| **POR / POD** | 收货地 / 卸货港 |
| **ETD / ETA** | 预计离港 / 预计到港 |
| **ATD / ATA** | 实际离港 / 实际到港 |
| **订舱号 / 提单号** | 订舱号先出，提单号后出；两者是**两套并存的号**，查询时可以互试 |
| **frp** | 内网穿透工具，把本机端口映射到公网服务器 |
| **tracking.v1** | 我们约定的统一结果格式，所有船司都转成这一种 |
