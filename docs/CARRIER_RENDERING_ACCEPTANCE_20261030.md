# 分船司货踪详情与真实文件验收

## 当前运行版本

本地入口为 `http://127.0.0.1:18088/workspace/tracking/overview`。在“本地货踪 JSON 预览”选择按船司结果 JSON，可筛选船司并打开详情。该预览只在内存显示，不创建票单、不覆盖快照、不更改客户绑定；刷新后需要重新选择文件。

Docker 已更新 frontend、tracking，backend、MySQL、模型 relay 的容器和数据卷保持。运行资产与本地构建逐文件校验，六项原业务数据计数保持。没有使用参考图中的虚构统计、节点或船名填充业务数据。

## 船司详情的渲染规则

总览保持统一的单号、船司、港口、日期和状态布局。详情按实际存在的箱明细、船期、运输分段、源条目及扩展字段组合。起终点文字不生成运输节点；缺失字段不推断为零、未离港或未到港。

| 数据层     | 常用字段                                                              | 处理方式                                               |
| ---------- | --------------------------------------------------------------------- | ------------------------------------------------------ |
| 查询与来源 | 船司代码/名称、提交单号、单号类型、查询状态、生成时间、策略、验证状态 | 单号按文本保留前缀和前导零；来源状态与运输状态分开     |
| 票级摘要   | 起运地、目的地、提单/订舱号、船名、航次、最新报告描述、声明箱数       | 没有来源值时不补造                                     |
| 船期       | ETD、ETA、ATD、ATA及来源时间文本/时区                                 | 预计与实际分开，保留原精度，缺失时隐藏                 |
| 箱明细     | 箱号、箱型、运输方式/条款、位置、状态时间、封号、重量                 | 只显示实际返回的行和列；不把票级封号分配给每个箱       |
| 运输分段   | 装卸港、船名航次、航线、各段船期                                      | 只有结构化分段才显示分段表                             |
| 源数据条目 | 原描述、原时间、地点、来源路径                                        | 本批数据混有页面标签和摘要，不能自动当作已发生运输事件 |
| 扩展字段   | 各船司的数组、对象、专有字段                                          | 保留字段路径，以安全文本或可展开 JSON 呈现             |

声明箱数与返回明细数独立显示。例如来源声明7箱、返回0箱明细时，两者均保留，不生成7个空箱行。NO_BUSINESS_DATA有独立空态。本批12票均为PAGE_TEXT且未经来源业务验证，页面明确提示。

COSCO、OOCL复用已有官方图片及来源记录；其他船司使用名称/代码文字徽标。展示支持不表示新增实时查询能力。

## 真实浏览器验收

在更新后的 Docker 页面实际选择用户提供的按船司 JSON，逐一打开并退出12家详情：HMM、SML、COSCO、MATSON、OOCL、MSC、EVERGREEN、HAPAG_LLOYD、KMTC、MAERSK、YML、ZIM。全部保留单号，按实际字段展示；桌面内页宽1271px、内容宽1271px，无页面横向溢出。390px外层和375px内页下，12条列表可用，移动侧栏展开正常。

SML封号数组、YML登船日期、HMM中转信息、COSCO装卸港详情保留。Hapag无业务数据时隐藏箱、船期和分段空区块；仅实际含分段的COSCO样本显示分段表。源条目未转成完成节点。

## Excel识别的边界

货踪任务表的左侧业务号与右侧船司查询号已区分，读取合并续行、日期和原始标识。真实文件有86个非空查询候选，85个语法有效。LEGACY模式44条可查询、47项问题；LOCAL_QUEUE模式按本地15家实际已实现适配器校验，75条可查询、15项问题。HEDE虽然有身份代码但本地尚无适配器，仍阻断。船司备注冲突、缺号和污染值不会自动忽略，整批保持提交前校验。

两份结果工作簿均不能误作查询任务表导入；按船司工作簿中无箱号列的结果页也保持阻断。

装箱XLS在实际页面识别为75包装、6925内装件、74575kg毛重。独立按合并锚点核对104明细与本地解析逐组一致。按米解读尺寸可得93.528148m³，原单声明96m³；原文尺寸单位不显式，保留确认门槛。本轮没有提交这些样本到原业务清单。

## Node接口对接

前端兼容单票 `tracking.v1` 和现有 `{ snapshot }` 响应；本地预览另支持数组及 `by_carrier` 批次。通用适配入口为 `tracking-service/public/tracking-v1-adapter.mjs`。真实接口应由受控服务调用并保留现有鉴权、超时和错误处理，不由浏览器任意代理用户输入的URL。

字段缺失用null或省略；不要用成功状态掩盖无业务数据。时间需要明确原文、时区、精度及实际/预计语义，未经确认的抓取文本保留为源条目。前后端的LEGACY/LOCAL_QUEUE构建与运行配置保持配对，旧预览明确使用LEGACY。

## FRP接口实测

本机8791与服务器FRP业务18791的health和已有任务结果均返回200，结果内容校验一致。通过现有FRP接口实际提交一票COSCO任务，POST返回202，10秒后completed，结果200、tracking.v1、QUERY_COMPLETED，任务ID、船司和原始输入单号匹配。另通过SSH在现有线上backend容器内请求FRP业务health，返回200及Chrome已连接。本轮没有部署替换线上Java服务，没有整批执行用户任务表或把样本写入业务票单。

Java桥接与映射的23项针对测试通过；前端字段归一化已兼容Java的typed fields及extraFields。货踪328项回归通过。证据及原始结果仅保存在忽略的.tmp目录，没有提交客户单号、隧道令牌或SSH凭据。
