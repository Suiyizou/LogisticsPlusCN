# 重构稳定性修复（2026-10-10）

本批对应审查报告 R01—R04，保持现有业务接口和角色页面。

## 2026-10-12 实机验收缺陷修复

- 失败登录、设备限制及密码修改失败通过 `AuthFailureAuditService` 独立保存。先等待当前
  事务完成，再开启审计事务，避免事件跟随登录回滚，也避免审计外键等待仍被登录锁住的
  用户行。成功登录事件继续与会话写入同事务；拒绝操作不会误提交其他会话修改。
- 明确清除 LLM Key 后不再回退到环境变量。环境 Key 仅在数据库没有显式配置时使用，
  不复制到数据库。后台保存 Key 使用既有 `SecretValueCodec` 的 AES-GCM 与独立用途标识；
  历史明文配置首次读取时转换为密文，配置损坏或密钥不匹配直接失败，不回退使用旧 Key。
- `V2__llm_key_inheritance.sql` 只删除 V1 未经管理员修改的空默认行，保留 `updated_by`
  已记录的历史清除操作；不修改既有 V1 校验值。手工建库脚本不再写入空 Key 默认行。
- Key 文件仍位于已有后端密钥卷，必须和数据库一起备份、恢复；丢失密钥不能解密已有配置。
  新增认证事务和 Key 生命周期回归，覆盖真实 Spring 事务代理、旧配置迁移和容器复验。
- 卷恢复命令显式覆盖后端 Java ENTRYPOINT 为 `sh`；发布脚本回归验证这一约束。

## 数据与页面一致性

- 快照作废恢复 `@Transactional`，先锁票单再修改快照，与追踪持久化采用相同锁顺序。
  快照必须属于当前票单且仍有效；清空操作同时检查当前快照 ID。快照、票单、客户发布
  状态及审计由同一个事务提交或回滚。
- 票单详情使用页面上下文版本与读取请求序号。更换票单、退出详情、切换模块和卸载组件
  会使旧上下文失效。旧响应、异常、保存后的 nextTick 回填不能修改新的详情页面。
- 读取或修改期间禁用详情编辑表单；保存、作废、刷新和删除互斥，避免船司刷新与人工保存
  相互覆盖。保存当前票单时继续保留另一部分尚未提交的字段；作废、刷新和删除完成后
  也核对当前页面上下文，切换票单会清空上一票的刷新提示。
