# 装箱工作流、智能导入与方案报告

本轮只整理装箱模块及其导入、导出链路，沿用现有权限、算法、箱型规则和本地业务数据。

## 工作流

- 默认入口改为 `/planner/cargos`。先整理货物，再计算方案，最后查看三维结果和导出。
- `/planner/config` 保留为低频“装箱设置”，从侧栏、清单和结果进入。设置已由既有 `cargo-planner-vue-state` 自动保存到当前浏览器；换电脑不自动共享。
- 清单默认显示可编辑表格，可切换到体积分布和包装尺寸概览；概览仍可进入货物编辑。模板与示例放在默认折叠区，减少首屏干扰。
- 表格/概览偏好和3D显示偏好分别保存为 `cargo-planner-cargo-view-v1`、`cargo-planner-scene-view-v1`，不会覆盖货物、箱型或计算参数；浏览器存储不可用时当前界面仍可使用。
- 3D默认只显示箱壳和货物。图例、重心、剩余空间和显示选项按需打开；方案选择、核验和原有导出入口保留。屏幕关闭重心叠加后，PDF与ZIP仍独立包含重心分析。

## 导入分流和复核

工作簿与截图使用不同任务，不能把图片当表格解析，也不能把模型结果直接视为可靠的装箱数据。

1. 常规Excel保留既有确定性导入与工作表/字段预览。智能Excel复用POI工作簿证据、只读工作簿工具、字段映射计划和确定性执行器。原文件、表格区间、单位及包装数量均参与复核。
2. 截图使用独立 `/api/text-recognition/tasks/image` 上传任务与 `cargo-image-v1` 协议，沿用后台模型配置。仅接受实际可解码的PNG/JPEG，限制5MB、单边8000像素和1200万像素；界面保留来源图、字段更正及包装身份核对。
3. 缺尺寸、无效或非整数包装数量、无效毛重、重复/含混包装身份不得悄悄补默认值；原始包号/唛头保留可核对。物理包装数量与内装产品数量分别处理。
4. 原图或原表的独立控制总量与候选行合计分别保留。未知来源总量明确标为未知，人工确认不能冒充自动守恒匹配，也不能清除原有总量冲突。
5. 截图先识别，再逐项对照来源确认。停止等待只停止前端接收，后台任务可能继续；换文件、关闭界面或会话变化后的旧结果不可写入当前货物。

模型本身不能保证每份文件零错误。当前隔离预览未证明后台配置的模型具备视觉能力，也没有把离线结构回归冒充线上识别准确率；联网使用需配置支持图片的模型并用实际业务文件验证。现有文件读取与字段校验无需依赖模型即可测试。

## 方案PDF

PDF新增完整方案总览、逐箱三维图与统一摆放编号、本箱货物清单、逐摆放坐标/尺寸/朝向/重量明细、偏载及计算说明，继续保留原有分层和剩余空间分析。遍历全部已有详算结果的箱，不只导出当前箱；未知数值显示“—”，原有禁止导出的偏载状态继续拦截。

摆放记录编号不等于经现场验证的装卸顺序。没有上游提供顺序时显示“—”，并说明门向、绑扎、地板点载和现场通道仍需人工复核。长货名按测量行高分页，不截断末行。

安全示例位于 `output/pdf/packing-report-example/`：中文和英文各19页，2箱、56件、6720kg、11.76m³，包含长货名与已换算成cm/kg的混合来源单位，明确标注EXAMPLE，不是实际客户装运方案。
