# 运单详情：快照、补充字段与增量

## 展示契约

列表使用公共快照：船司、查询标识、起终港、最新事件、预计/实际离到港时间。详情根据实际存在的数据展示航段、集装箱、里程碑和船司专属补充信息，不要求每家返回 COSCO 的全部字段。

- `summary`、`keyTimes`、`routingLegs`、`containers`、`references` 供业务组件使用。
- `sourceDetails.fields` 保留映射之外的业务字段、来源路径、原始结构和值。事件、船名、状态及箱记录的原文也可查看。补充区首次展开时才构建内容。
- `sourceDetails` 中的查询状态、警告和无业务结果继续保留。返回成功不代表业务信息经过验证，也不代表所有箱明细已采集。
- 展示值有长度和字段数量上限，不能把页面视为无限制的原始响应归档。若业务需要完整原始包归档，应在接口持久化层单独保存。

## 单包交付与历史读取

`snapshot.deliveryMode=SINGLE_RESPONSE` 是默认模式。Java 从一次 API 结果中映射并保存同票的航段、集装箱、事件和来源字段，页面按已返回的数据展示。打开票单或历史快照只读取已保存的结果。没有 `deliveryMode` 的历史快照也可直接查看，旧的 `pendingRefresh` 或 `carriedForward` 标记不会触发补拉或显示补拉失败。

`LEGACY_SUPPLEMENTAL` 仅用于显式启用拆分补充能力、且适用的旧适配器明确报告需要补充的结果。启用方式见[本地 Chrome 货踪 API 对接](LOCAL_CHROME_TRACKING_API.md)。本地队列始终采用单包交付。

## 增量更新语义

完整快照仍代表本次完整查询结果；明确的箱级补充才递归合并嵌套字段、保留已有非空值和事件历史。空值不会抹除有用值，`0` 和 `false` 不被当成空值。事件按来源、事件名、时间、预计/实际类别、地点和箱号识别；旧请求不能覆盖后来已经刷新出的字段。

ETA 是预计到港，ETD 是预计离港，交付日期单独处理。来源没有提供实际/预计类别的时间只保留来源时间，不由页面猜测。

## 国家、地点与地图

先解析明确的国家字段，兼容 ISO 2 位/3 位、国家名称和明确别名；缺失时使用可核对的港口或 UN/LOCODE。地点字符串中的州/省缩写不能直接当国家，例如 `LOS ANGELES, CA` 是美国洛杉矶，`CA` 在明确国家字段中才是加拿大。无法确认时保留原文，不显示猜测的旗帜。

总览不加载地图模块或为地图抓取全部分页。详情按需加载本票航线卡片，地图只表示港口节点关系，不表示实时船位或实际航行轨迹。返回总览保持原有筛选、页码及滚动位置。

## 增加船司的验收

每家至少保存成功、缺字段、无业务数据和错误四类去敏样本。核对公共字段的语义、原始补充字段是否保留、ETA/ATA 是否分开、起终港是否可定位，并通过真实页面检查标志、旗帜、箱明细、折叠补充区和空态。不能只以 HTTP 200 或 JSON 可解析作为完成标准。

2026-11-03 本地真实文件核查覆盖 12 家船司。文件中 COSCO 声明箱量但没有返回对应箱明细，Hapag-Lloyd 无业务数据，部分船名包含来源抓取噪声；这些属于上游采集质量问题，页面保留提示与原值，不生成缺失信息。

## 2026-11-04 统一详情呈现

各船司共用身份、起终地、时间、最新状态、参考号、运输节点及箱明细框架；按返回信息显示具体内容。没有分类的来源时间使用“船司显示的离/到港时间”，不冒充实际或预计时间。只有来源历史时展示该历史，不补造 COSCO 式里程碑。声明箱量与实际返回的箱明细条数分开显示。

桌面详情中小地图与参考信息并排，移动端顺序堆叠；总览不加载地图资源。船司扩展字段及原始记录放在公共业务内容之后并按需展开。总览船司图片最大为 120 × 34 px。截图中的 SHA、IAH、TULSA 等地点补充国家识别；不会由机场简称虚构海港坐标，规则与来源见[地点规范化说明](logistics-map-geography.md)。

本地 Edge 检查覆盖 12 家船司真实文件样本，以及数据库中 HMM 的 6 条箱明细、COSCO 的 8 条箱明细；检查桌面、移动端、国旗、详情返回总览及没有自动补充请求。此检查不代表线上 FRP 连通或完整发布任务流程已经实现。服务器草稿及发布执行的现状与建议见[任务发布流程设计](tracking-task-publishing-design.md)。
