# 跟踪工作台与统一智能导入

## 跟踪界面与导航

本轮按船司工作台的信息层级重新组织跟踪页，查询表单仅保留船司、单号类型、单号与查询操作；查询策略由系统自动选择。移除了用户可见的技术通道选项及缺乏实际依据的路线百分比。

- 摘要按船司身份、单号、最近报告状态、起讫港与关键时间排列，明确显示原记录同步时间，不将旧快照包装成实时定位。
- 使用从中远海运集运及OOCL官网核实的原始品牌文件，保持原图比例；来源与哈希记录在 `tracking-service/public/carriers/SOURCES.md`。
- 运输节点区分实际、预计和待报告；实际与预计时间分别保留，并显示来源时区。当前节点由实际事件确定，不从 `active` 标志或目的港地点推断完成。箱级轨迹采用相同证据口径。
- 工作台侧栏按运输跟踪、装箱工具、业务协同和系统管理分组。父项只展开，二级入口直接导航；仍依据原有角色权限过滤，保留装箱与后台操作的禁用/忙碌守卫。

设计参考了 [Maersk的里程碑说明](https://www.maersk.com/support/faqs/2024/01/23/milestones-is-maersk-tracking)、[Hapag-Lloyd跟踪与可视化](https://www.hapag-lloyd.com/en/online-business/track/track.html) 以及 [CMA CGM的跟踪指南](https://www.cma-cgm.com/assets/public/page-complex-documents/Shipment%20tracking%20-%20Flyer%20English%20-%202022.03.18.pdf)，没有复制其商业系统或虚构船舶位置。

## 统一智能导入

装箱清单、配置区及旧 `/smart-import`、`/excel` 地址均进入同一智能导入流程。旧地址保留其他查询参数与锚点，重定向至 `/planner/cargos?import=smart`。上传后自动识别Excel或PNG/JPEG，用户不再选择“快速导入”。确定性的文件读取仍作为内部证据校验保留。

Excel继续使用POI工作簿证据、只读工具调用、映射计划和确定性执行器。图片使用独立视觉任务。Excel可以附加同一原表的完整截图；当前版本需要提供原图，没有将自行重排的表格渲染冒充独立视觉证据。

交叉核对按明确的物理包装身份匹配，比较数量、cm尺寸、kg单包毛重、名称/型号和装载约束，并保留双方来源行、工作表及独立控制总量。匿名包装组、重复身份、缺字段、结果未完成、原始硬阻断或两路冲突会阻止导入。不按行顺序猜配，不因总量相同而认定逐项一致，不用人工确认清除源数据冲突。

两路候选一致后仍需逐项对照来源并明确确认。更换文件、修改字段或产生新结果会撤销确认；旧请求返回不能覆盖新来源。由统一入口提供的文件不会被子审阅组件的其他上传入口悄悄替换。

## 本地模型通路

为完成实际模型验证，新增可逆的预览专用TLS透传relay，仅允许backend访问 `api.deepseek.com:443`。backend仍不连接外网网段，tracking保持原来的出网隔离，船司自动更新仍关闭。relay限定来源IP及SNI，不终止TLS、不记录HTTP内容、不公开端口。

- 启用模型通路：`node scripts/dev-preview.mjs llm-on`。
- 带模型通路启动现有项目：`node scripts/dev-preview.mjs start --no-build --llm-relay`。
- 撤回模型通路：`node scripts/dev-preview.mjs llm-off`，不删除数据库卷。

已验证目标TLS连接、证书校验，以及错误SNI、其他公网目标和tracking访问被拒绝。MySQL容器及原始业务计数保持不变；backend为接入专用内部网络按预期重建过。
