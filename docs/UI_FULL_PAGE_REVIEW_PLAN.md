# logisticspluscn 整页 UI 设计稿与全页面检查计划

日期：2026-10-28。只读决策基线：`codex/logisticspluscn-ui-a`，HEAD `8f7e993`。本文件不修改应用源码，不代表下列页面已验收。

## 1. 本轮目标与交付定义

用户最新纠正优先于前稿：导航只需借鉴参考图的宽面板、分组和信息层级，不要求完全仿制；需要生成的是完整 UI 界面设计图，而不是港口、船舶等配图；最终必须能逐页打开现有系统，查看有数据的列表、详情、页内状态和弹窗。

保留本轮已实现的深海蓝、陶土橙、Inter/Noto Sans SC、组件与动效，不另起一套风格，也不把真实页面替换成静态演示。六张整页设计稿负责确定代表性布局；全部页面的浏览器检查是另一份交付，两者不能互相充数。

最终交付至少包含：

1. 六张完整 UI 设计图，每张标注对应页面、状态、桌面尺寸及设计稿身份；图不是可交互产品，截图不是生图。
2. 可点击的本地检查索引，列出本文所有现行路由、真实记录详情链接、所需身份和页内操作路径。
3. 按实际状态保存的全页截图及关键弹窗截图。列表有数据、详情可打开、弹窗可达，才构成该项正常态证据。
4. 无数据、缺附件文件、未连接后端、隐藏旧 UI 分别说明，不能统一写成“已覆盖”。

## 4. 页面完成口径

每项分别记录 `可达`、`非空正常态`、`子视图`、`详情/弹窗`、`角色`、`桌面`、`窄屏`、`证据`。用以下状态，不用笼统的“已覆盖”：

- **待检查**：仅由路由或源码确认存在。
- **缺数据**：路由可达，但没有满足本项的真实记录/文件。
- **已检查正常态**：实际打开有数据页，布局与主要交互有证据。
- **已检查异常态**：另验证无结果、失败、权限或等待，不替代正常态。
- **设计预览**：明确没有对应数据/执行后端的获授权预览。
- **休眠 UI**：源码存在，当前标准用户流程没有可达入口；不得算作已验收。

下列矩阵全部从“待检查/待填真实 ID”开始。之前的截图可以复用为对应布局证据，但不能替代本次历史数据连接与真实记录可达性。

## 7. 检查索引与证据格式

建议交付根目录为 `output/ui-full-page-review/`，不与生图素材混放。可由实现人员生成一个本地只读索引 HTML 或文档，不新增业务 API；索引本身需明确“检查目录”，不能冒充产品导航。

每个索引项包含：矩阵 ID、中文页面名、可点击的实际 URL、所需身份、数据别名/就绪状态、详情/弹窗的按钮路径、桌面图、375/390px 图、当前问题。动态详情使用导入后真实 ID；只有列名和空白行的截图标为“缺数据”，无原文件的预览标为“缺文件”。原始敏感 ID/记录截图只保存在用户本地，不放入外部整页生图提示。

建议证据命名：`P01-home-desktop-full.png`、`B03-customer-a-mobile-full.png`、`D29-files-open-desktop.png`；整页图需滚到内容底部确认页脚/分页/末行，弹窗图需包含标题、主体和底部按钮。键盘焦点、进入/退出、菜单变化和 loading 使用短录屏或分状态截图补证；单张静态图不能证明动效。

所有主页面桌面正常态都要实际打开。每类布局至少完成 375/390px、英文、200% 缩放；出现长表、长文件名、长客户名、复杂弹窗的页面应单独覆盖窄屏，而不是抽测首页后推断。表内横滚可接受，整页溢出必须修；主操作、关闭按钮、错误文案不可被固定区挡住。一次成功打开不替代刷新直达、登录后回跳、浏览器返回。

## 8. 可执行顺序与责任边界

1. **根代理协调运行环境**：核实健康与连接目标，明确当前主入口；指派 Sol 在独立库导入/迁移，不改设计方向。
2. **数据恢复人员**：完成 manifest，找出非空客户/票单/快照/附件/公告/交接记录；报告缺失类别与原文件路径，不能以新建空库替代历史库。
3. **根代理生图**：按 G01–G06 逐张生成完整 UI comp，先看清楚整页布局，再用于现有 UI 的具体修正；不把配图再交成整页稿。
4. **页面覆盖人员**：建立实际可点击索引，先 ADMIN 路径，再 BUSINESS、内部 OVERSEA_AGENT、普通 CUSTOMER、客户型 OVERSEA_AGENT；每个动态详情都从真实列表点击一次。
